# Database and API

The NestJS API owns all published content. The Angular application reads `GET /api/portfolio`; it never substitutes demo content or browser storage when the server fails. Public content is initialized once from `shared/portfolio.seed.ts`. Subsequent starts preserve the database. Legacy `localStorage` and IndexedDB are accessed only by the explicit import action.

SQLite is appropriate for this single-site CMS: low write concurrency, a single API process and a durable local volume. WAL, foreign keys and a five-second busy timeout are enabled. The database is accessed through Node 24's `node:sqlite` API. It can be replaced with PostgreSQL by replacing `PortfolioRepository`/`Database` without changing the frontend's content contract. Do not run multiple API replicas against a network-mounted SQLite file.

Settings use small JSON documents for fixed groups of scalar fields, rather than an untyped key/value table for every field. Projects, shared relationships, ordered lists and files are modeled separately. The shared TypeScript content contract is in `shared/portfolio.models.ts`; Zod validation is in `backend/src/portfolio.schema.ts`.

## Content writes

Each editable sidebar page has exactly one **Save page** action in the admin toolbar. It builds a candidate from the last published snapshot and all fields owned by that page, then sends it atomically to `PUT /api/portfolio` with the editor's revision. Hero includes introduction, resume and badges; Header includes logo, CTA and navigation; About includes all statistics and skills; Footer includes copy and platforms; Cases includes all cards, details, stories, metadata, recommendations, ordering, creation and deletion across all cases. Other pages' drafts remain local. Server sanitization is reconciled by ID, preserving edits typed while saving. New referenced tags are included as dependencies; deletions clean related records. Explicit Cases-page feature toggles are tracked separately so pending Home-page membership changes are not published through Cases. Files upload immediately; their content references publish with the owning page. Media management and backup/restore have immediate actions. Custom HTML is removed from admin navigation, public rendering and singleton setting endpoints; legacy fields are accepted for backup compatibility but ignored and returned empty.

Every content mutation requires `If-Match: <revision>` from the most recent snapshot. Stale edits get `409`; their draft stays intact. Each admin draft remembers the revision it was based on. Use **Reload from server** to intentionally discard that draft and start from the latest version. Granular CRUD endpoints use the same validation, repository and revision checks.

```json
{ "data": { "hero": "...other PortfolioData fields..." }, "revision": 12 }
```

The actual `data` is the full `PortfolioData`, not the abbreviated example. Snapshot responses are returned after all content mutations.

## Routes

All paths below are under `/api`. GET content endpoints are public unless noted. Writes require an authenticated session cookie plus `X-Portfolio-Request: 1`. Content writes also require `If-Match`. JSON request bodies have a 10 MB limit.

| Method        | Path                                | Body / behavior                                                                                                                                            |
| ------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET           | `/health`                           | Database health.                                                                                                                                           |
| GET           | `/portfolio`                        | Full public snapshot and revision.                                                                                                                         |
| PUT           | `/portfolio`                        | Complete `PortfolioData`; atomic page saves/import.                                                                                                          |
| POST          | `/portfolio/reset`                  | Reset published content to the server seed; preserve media and users.                                                                                      |
| GET           | `/projects`                         | Ordered cards.                                                                                                                                             |
| GET           | `/projects/:id`                     | Card plus `detail`.                                                                                                                                        |
| POST          | `/projects`                         | Card fields, optional `id`, optional full `detail`; generates an ID otherwise.                                                                             |
| PATCH         | `/projects/:id`                     | Partial card fields and optional partial `detail`; project ID stays stable.                                                                                |
| DELETE        | `/projects/:id`                     | Delete card, details, featured copy and recommendations; detach other home-card links.                                                                     |
| GET, POST     | `/projects/:id/sections`            | List/create story sections.                                                                                                                                |
| PATCH, DELETE | `/projects/:id/sections/:sectionId` | Update/delete a story section. Nested subsections are part of the section document.                                                                        |
| GET, POST     | `/home-projects`                    | List/create independent home cards.                                                                                                                        |
| PATCH, DELETE | `/home-projects/:id`                | Edit/delete a home card.                                                                                                                                   |
| GET, POST     | `/tags`                             | List/create tags.                                                                                                                                          |
| PATCH, DELETE | `/tags/:id`                         | Rename/change link or delete tag and its relationships.                                                                                                    |
| GET, PATCH    | `/settings/:section`                | `header`, `hero`, `about`, `footer`, `content`. Settings accept partial objects. |
| GET, POST     | `/collections/:name`                | List/append an ordered item. Names: `navigation`, `badges`, `partners`, `mindsets`, `skills`, `stats`, `experiences`, `testimonials`, `photos`, `socials`. |
| PATCH, DELETE | `/collections/:name/:index`         | Zero-based index with the current revision. String collections use `{ "value": "..." }`. Reorder via the aggregate endpoint.                               |
| GET           | `/auth/session`                     | `{ "user": null }` or signed-in username.                                                                                                                  |
| POST          | `/auth/login`                       | `{ "username": "admin", "password": "..." }`. Creates an eight-hour session.                                                                               |
| POST          | `/auth/logout`                      | Revoke current session and expire cookie.                                                                                                                  |
| GET           | `/media`                            | Admin only: files, metadata, original URLs and published usage.                                                                                            |
| POST          | `/media`                            | Admin only: multipart `file` plus `kind=image                                                                                                              | document | attachment`. |
| GET           | `/media/:id/file`                   | Public original bytes. Images inline; documents/attachments download with original filename.                                                               |
| DELETE        | `/media/:id`                        | Admin only: delete an unused uploaded file. Referenced files return `409`.                                                                                 |

File replacement means uploading a new immutable file and saving its new URL. Clearing a media field detaches it in the draft; after saving, an unused file can be deleted from **Uploaded files**. This prevents deleting files still used by another card, page or rich-text block. Cancelling a draft can leave unused uploads; the same library can remove them.

Floating badge SVGs: self-contained SVG up to 1 MB, uploaded with `kind=svg` and stored as image media. XML is validated; scripts, active elements, event handlers and external resources are rejected. Original safe SVG bytes are preserved and served with a restrictive CSP. Images: JPG/PNG/WebP/GIF/AVIF up to 8 MB. CV: PDF/DOC/DOCX up to 15 MB. Attachments: those formats plus ZIP/TXT/CSV/JSON up to 15 MB. Server-side content inspection checks actual image/document types. Uploads are never resized or recompressed. Existing `/assets/portfolio/...` images remain bundled static assets; their editable references are stored in the database.

## Authentication and deployment

`npm run setup` installs the backend dependencies and creates an ignored `backend/.env` with a randomly generated first admin password. On the first successful start the server hashes that password; later starts do not change it. Editing `ADMIN_PASSWORD` after the admin account exists does not rotate the stored password.

Cookies are HttpOnly and SameSite=Strict. Production cookies require HTTPS. Browser write requests must carry the custom API header; foreign origins are rejected. Configure exact frontend origins in `FRONTEND_ORIGINS`. Login has a per-IP retry limit. Database constraints, schema validation, parameterized SQL and server HTML sanitization apply to every write.

Serve the frontend and `/api` from the same origin. During development Angular proxies `/api` to `127.0.0.1:3000`; production Nest serves the Angular build directly. `netlify.toml` alone is no longer a full deployment: static hosting must proxy `/api` to this backend with a durable database/upload volume.

For an infrastructure backup, stop the service and copy the entire data directory (including any SQLite WAL/SHM files) and upload directory together. For portable content backups, use **Download full backup**: its JSON includes the content and referenced uploaded files. **Restore JSON backup** and **Import old browser content** upload the original files and replace published content after confirmation; they preserve the old browser data. Content backups do not contain passwords or sessions.

Official references: [Nest file uploads](https://docs.nestjs.com/techniques/file-upload), [Node 24 SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).

The original hero Figma/design SVGs are the default two `hero.badges` records in schema version 4. Badge artwork is editable under Floating badge; each position keeps its original CSS floating animation. Use default SVG restores the bundled graphic. Profile image changes do not modify these records. Old browser backups are upgraded without replacing existing custom badge rows.

Footer platforms use ordered `footer_socials` rows with `label`, `link`, optional `icon` (built-in symbol) and optional `image` (uploaded media or image URL). Migration 3 adds these columns without replacing existing rows; existing published content gets a new revision to prevent stale drafts overwriting it. `/collections/socials` supports add/update/delete/reorder through the existing collection API. SVG icons upload as `kind=svg`, raster icons as `kind=image`; public rendering prefers the custom image over the built-in symbol.

Case study tag links point to `/projects?tag=TAG_ID`. Repeated `tag` query parameters select multiple tags with OR matching; selecting, removing and clearing filters updates the URL. Tag `link` metadata remains stored for compatibility. Resume actions fetch the configured file and trigger a blob download; missing files and failures display an error without navigation. External resume URLs require CORS; server-hosted uploads work directly.
