# Adel Portfolio

پورتفولیوی Angular با بک‌اند NestJS و دیتابیس SQLite. همه محتوای منتشرشده از API خوانده می‌شود؛ تغییرات پنل و فایل‌های آپلودشده روی سرور ذخیره می‌شوند و میان دستگاه‌ها مشترک‌اند.

## اجرای توسعه

Node.js نسخه 24.18 یا جدیدتر در شاخه 24 لازم است. نسخه پیشنهادی در `.nvmrc` ثبت شده است.

```sh
nvm use
npm ci
npm run setup
npm run dev
```

- سایت: آدرس `Local` در خروجی اجرای Angular. پورت پیش‌فرض 4200 است؛ اگر اشغال باشد، پورت دیگری انتخاب می‌شود. پنل همیشه در مسیر `/admin` روی همان آدرس سایت است. از آدرس یا پورت اجرای قبلی استفاده نکنید.
- API: `http://127.0.0.1:3000/api`
- نام کاربری اولیه: `admin`
- رمز اولیه: مقدار `ADMIN_PASSWORD` در فایل محلی و نادیده‌گرفته‌شده‌ی `backend/.env`. دستور setup رمز تصادفی می‌سازد و رمز را در خروجی چاپ نمی‌کند.

`setup` فایل تنظیمات موجود یا دیتابیس را بازنویسی نمی‌کند. هر دو دستور `npm start` و `npm run dev` ابتدا بک‌اند را آماده و سپس فرانت را اجرا می‌کنند. برای اجرای جداگانه از `npm run start:frontend` و `npm run api:dev` در دو ترمینال استفاده کنید. دستور اجرای مشترک، پروکسی `/api` را با پورت بک‌اند هماهنگ می‌کند و آرگومان‌های `--host` و `--port` را به Angular می‌فرستد. پورت بک‌اند از `backend/.env` یا متغیر `API_PORT` خوانده می‌شود. در اجرای جداگانه، Angular از `proxy.conf.json` استفاده می‌کند.

## اجرا از بیلد

```sh
npm run build:all
npm run api:start
```

سپس سایت، پنل، API و فایل‌ها همگی در `http://127.0.0.1:3000` در دسترس‌اند. Nest خروجی Angular را نیز سرو می‌کند. در محیط واقعی، HTTPS و `NODE_ENV=production` را تنظیم کنید و آدرس دقیق سایت را به `FRONTEND_ORIGINS` بدهید.

اجرای Docker پس از `npm run setup`:

```sh
docker compose up --build
```

Compose برای اجرای محلی حالت development دارد؛ برای محیط HTTPS از `NODE_ENV=production docker compose up --build -d` استفاده کنید. دیتابیس و فایل‌ها در volume پایدار `portfolio-data` نگهداری می‌شوند. کانتینر بدون دسترسی root اجرا می‌شود.

## مدیریت محتوا

پنل انگلیسی است و کنار فیلدها و بخش‌ها، «؟» توضیحات فارسی را در مدال باز می‌کند.

- **Hero and resume / Header and logo**: معرفی، عکس، رزومه، لوگو، منو و دکمه‌ها.
- **Case studies / Home projects / Tags**: ایجاد، ویرایش، حذف و ترتیب پروژه‌ها؛ تمام بخش‌های داستان، متن غنی، عکس، پیوست، متادیتا، پیشنهاد پروژه بعدی و تگ‌های مشترک با لینک اختیاری.
- **About / Experience / Testimonials / Gallery / Skills ticker / Footer / Site copy**: سایر محتوای سایت.
- **Uploaded files**: فایل‌های سرور، وضعیت استفاده و حذف فایل بدون استفاده.
- **Backup and reset**: خروجی کامل، بازگردانی JSON، انتقال نسخه قدیمی مرورگر و بازنشانی محتوای سرور.

هر صفحهٔ سایدبار یک دکمهٔ **Save page** دارد که تمام ویرایش‌های همان صفحه را با هم ذخیره می‌کند. مثلاً در **Hero and resume** معرفی، رزومه و گرافیک‌ها با هم ذخیره می‌شوند؛ در **Case studies** تغییرات همهٔ کیس‌استادی‌ها، از جمله کارت‌ها، معرفی، متادیتا، داستان‌ها، ایجاد، حذف و ترتیب‌ها ذخیره می‌شوند؛ در **Footer** متن و لینک‌های اجتماعی با هم ذخیره می‌شوند. پیش‌نویس صفحه‌های دیگر منتشر یا پاک نمی‌شود. **Uploaded files** و **Backup and reset** عملیات مستقیم دارند. تعارض نسخه با پنل دیگر همچنان بررسی می‌شود؛ **Reload from server** نسخه تازه را پس از تأیید می‌گیرد و **Discard changes** پیش‌نویس را کنار می‌گذارد. بخش Custom HTML حذف شده است.

صفحه‌های عمومی بدون ورود قابل خواندن‌اند؛ همه عملیات تغییر و آپلود به نشست معتبر ادمین نیاز دارند. اگر API در دسترس نباشد، صفحه خطا و تلاش مجدد نمایش داده می‌شود، نه محتوای نمونه یا نسخه محلی قدیمی.

## انتقال محتوای نسخه قبلی

در همان مرورگر و همان origin که نسخه قدیمی ویرایش شده بود وارد پنل شوید. در **Backup and reset**، دکمه **Import old browser content** را بزنید. محتوا از localStorage و فایل‌ها از IndexedDB خوانده می‌شوند، فایل‌های اصلی روی سرور آپلود می‌شوند و محتوا پس از تأیید در دیتابیس جای می‌گیرد. داده قدیمی مرورگر پاک نمی‌شود.

اگر origin عوض شده است، از نسخه قبلی پشتیبان JSON کامل بگیرید و با **Restore JSON backup** وارد کنید. نمونه اولیه فقط یک بار در دیتابیس تازه درج می‌شود؛ ری‌استارت یا بیلد اطلاعات ذخیره‌شده را عوض نمی‌کند.

## ساختار و تست

- `backend/src`: ماژول‌های Nest، کنترلرها، احراز هویت، اعتبارسنجی، فایل‌ها و repository.
- `shared/portfolio.models.ts`: قرارداد مشترک داده بین سرور و Angular.
- `shared/portfolio.seed.ts`: داده نمونه برای ساخت دیتابیس اولیه و بازنشانی صریح.
- `backend/data/portfolio.sqlite`: دیتابیس محلی پیش‌فرض.
- `backend/data/uploads`: اصل فایل‌های آپلودشده.
- [طراحی دیتابیس و مستندات کامل API](docs/DATABASE.md): جدول‌ها، روابط، مسیرهای CRUD، نسخه‌بندی، احراز هویت و استقرار.

```sh
npm test -- --watch=false
npm run api:test
npm run build:all
```

تست بک‌اند یک دیتابیس موقت مستقل می‌سازد و خواندن عمومی، ورود، مجوز تغییر، CRUD، روابط، تراکنش، تعارض نسخه، فایل اصلی، پاک‌سازی ارتباط‌ها و ماندگاری پس از ری‌استارت را بررسی می‌کند.

تست مرورگری کامل (با دیتابیس موقت، رمز تصادفی و مرورگرهای مستقل):

```sh
npx playwright install chromium
npm run test:e2e
```

برای استفاده از Chrome نصب‌شده، متغیر `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` را به مسیر اجرایی آن تنظیم کنید. این تست ورود، CRUD از پنل، اشتراک داده میان مرورگرها، اصل فایل‌ها، انتقال IndexedDB، بازگردانی پشتیبان و تعارض دو ادمین را بررسی می‌کند.

در **Hero and resume → Floating badge** دو گرافیک فعلی پیش‌فرض‌اند. برای جایگزینی هرکدام، **Badge SVG** را آپلود و **Save page** را بزنید؛ جایگاه و انیمیشن قبلی حفظ می‌شود. **Use default SVG** گرافیک اصلی همان جایگاه را برمی‌گرداند. فایل SVG تا ۱ مگابایت پشتیبانی می‌شود.

در **Footer and social links** با **Add** پلتفرم جدید بسازید و نام، لینک و آیکن آماده یا **Platform image / icon** را تنظیم کنید. آپلود عکس و SVG پشتیبانی می‌شود؛ فایل آپلودشده جایگزین آیکن آماده خواهد شد. ترتیب و حذف پلتفرم‌ها هم قابل تنظیم است. تغییرات با **Save page** منتشر می‌شوند.

هر دو دکمهٔ رزومه فقط فایل تنظیم‌شده در **Hero and resume → Resume** را دانلود می‌کنند. اگر فایلی تنظیم نشده باشد، صفحه جابه‌جا نمی‌شود. برای لینک فایل خارجی، سرور مقصد باید دسترسی CORS دانلود را مجاز کند؛ آپلود رزومه در پنل این محدودیت را ندارد.

کلیک روی تگ پروژه، فهرست کیس‌استادی‌ها را با آدرس `/projects?tag=TAG_ID` باز می‌کند. در فهرست، از **Filter by tag** چند تگ انتخاب کنید؛ پروژه‌های دارای حداقل یکی از تگ‌ها نمایش داده می‌شوند. هر تگ با × و همه با **Clear filters** حذف می‌شوند. فیلترها در لینک و تاریخچهٔ مرورگر حفظ می‌شوند.
